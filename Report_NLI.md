# Report — composite negation detector: content gate → cancellation veto → NLI

Generated by `experiments/composite/report_composite.py` from `experiments/composite/results_composite.json`. Every number is read from that file. Seed 0. TEST scored 1 time by this experiment.

## 1. What we did

Three stages, cheapest decision first. A pair stopped at stage 1 or 2 is predicted *not a negation* and never reaches NLI.

| stage | what it checks | cost per pair (ms, CPU) | failure it targets | measured number that motivated it |
| --- | --- | --- | --- | --- |
| 1 content gate | raw cosine(A,B) < t1 = 0.36 → not a negation, stop | 36.4 (embed both sides with mpnet); ≈0 if embeddings already exist | NLI calls unrelated pairs contradictions | NLI alone FPR on test: random_pair 95.0%, sts_low 89.0%, snli_neutral 27.4% |
| 2 cancellation veto | B has ≥ 2 cues in one clause_scope that cancel by parity, AND v2 polarity(A) = v2 polarity(B) → not a negation, stop | 4.6 (spaCy parse + cue extraction of both sides) | NLI reads *never fails to* / *not impossible* as contradiction | NLI alone K1 FPR on DEV: 18.7% (polarity v2: 5.5%) |
| 3 NLI | P(contradiction) from cross-encoder/nli-deberta-v3-base ≥ threshold (0.00125, DEV) | 40.2 | finding negations, including cue-free lexical ones | NLI alone recall on test: verbal 98.6%, antonym 97.9%, other 97.8% |

Costs are measured on 256 DEV pairs with fresh model runs (no cache), batch 16, CPU, 8 torch threads. **The gate is not cheap when it has to embed**: mpnet on two sentences costs 36.4 ms against 40.2 ms for one NLI forward pass on the concatenated pair. See the wall-clock table in section 3.

**Fitting (DEV only).** NLI threshold: Youden's J on DEV, as in experiments/polarity. Gate: for each similarity, t1 on a 0.01 grid maximising DEV Youden's J of gate → NLI, subject to the gate keeping ≥ 95% of DEV positives; the similarity with the higher J wins. Stage-3 threshold refit on DEV per cascade (it came out equal to the NLI-alone threshold). The veto has no parameters.

| similarity | best t1 | DEV J of gate → NLI | DEV positives the gate keeps |
| --- | ---: | ---: | ---: |
| **cos** | 0.36 | 0.8835 | 99.6% |
| c_resid | 0.40 | 0.8831 | 99.4% |

Chosen: **cos, t1 = 0.36**. c_resid is within 0.0004 J — the choice between them is not meaningful. The recall floor was not binding: J peaks at t1 = 0.36, where the gate costs 0.4% of DEV positives. The highest t1 the floor allows is 0.58 (gate keeps 95.4%, DEV J 0.8497). End-to-end DEV recall cost of the gate: 95.1% → 94.7%; test: 98.5% → 97.4%.

**Configuration choice (VALIDATION).** Candidates NLI / NLI+gate / full, by validation accuracy, a tie going to the simpler one: nli 84.2%, nli_gate 93.3%, full 93.3%. **Chosen: nli_gate** (NLI + content gate). NLI+gate and full tie on validation because validation contains no K1 pairs and the veto fires on 1 validation pair(s). All five ablation rows were scored on TEST in that single run, with every parameter frozen.

## 6. Caveats

1. **TEST set reuse.** This TEST split was already scored once by experiments/polarity (NLI was one of its baselines there). This is its second use across experiments. No composite parameter (similarity choice, t1, thresholds, configuration) was tuned on it; TEST was scored 1 time here, after everything was frozen (`test_scorings.json`).
2. **Our OS/CN dataset is generator output**, and the polarity module (hence the veto) reads the generator's own lexicons, so the K1 number is flattering: the veto recognises its sibling's vocabulary. The headline numbers are CANNOT phase 2. K1 lives in DEV, the split every threshold was fit on (the veto itself has no parameters).
3. **Small n.** K1: 91 pairs. SemAntoNeg: 41 in phase 2 (27 in TEST); one pair there is 2.4 points. The veto result on SemAntoNeg (no change) is weak evidence either way: those pairs mostly swap an antonym (*good* / *not evil*) rather than stack two cues in B, so the veto as specified rarely applies to them.
4. **One seed (0)**: one phase-2 validation/test partition, one sample of error examples. No confidence intervals.
5. **Validation lacks the veto's target.** Validation has no K1 and NLI already gets its SemAntoNeg pairs right, so it could not choose between NLI+gate and full; the tie rule chose the simpler one.
6. **The NLI threshold is tiny** (0.00125): Youden's J on DEV, where positives dominate. That is why NLI alone flags almost every unrelated pair, and why the gate has so much to remove. A higher NLI threshold would remove some of the same errors; it was not tried: Youden's J on DEV was kept for comparability with experiments/polarity, whose NLI baseline this is.
7. **Timing** is one CPU (8 threads), batch 16, 256 pairs; on a GPU the ratios change. The veto is only evaluated on pairs the gate passes, and its cost is charged only to the full system.
8. The veto follows the brief literally: it looks for cancellation **in B** only. CANNOT pairs run in both directions; a symmetric veto (cancellation in A, too) was not tried.
